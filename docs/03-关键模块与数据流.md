# 03 · 关键模块与数据流

本文给出模块职责、依赖关系，以及几条端到端的数据流。

---

## 1. 模块清单

| 模块 | 类型 | 职责 | 关键入口 |
|---|---|---|---|
| `AntiCheatPlugin` | `BasePlugin` | 插件入口：读配置、建模块、挂补丁、生命周期 | `Load()` / `Unload()` |
| `AntiCheatRuntime` | 静态类 | 纯托管运行时：持有全部模块，驱动帧循环 | `Initialize()` / `Tick()` |
| `GameBridge` | 静态类 | **所有** il2cpp 访问的集中入口，多路径降级 | 见文档 05 |
| `AntiCheatConfig` | 类 | 全部配置项定义 | 构造函数内 `Bind` |
| `PlayerTracker` / `PlayerTrack` | 类 | 每玩家轨迹、快照、各类计数与豁免时间戳 | `GetOrCreate()` / `Push()` |
| `BehaviorAnalyzer` | 类 | 行为与事件检测算法（纯逻辑） | `Analyze*` 系列 |
| `VerdictEngine` | 类 | 证据汇总、等级判定、处置触发 | `Submit()` / `Evaluate()` |
| `ModScanner` | 类 | 静态扫描已加载插件 | `Scan()` |
| `CheatSignatureDb` | 静态类 | 作弊特征库（黑名单 / 灰名单 / 默认信任） | 静态字段 |
| `RpcFloodGuard` | 类 | RPC 速率保护（滑动窗口） | `TryRecord()` |
| `RpcEventRecorder` | 类 | 每玩家 RPC 环形缓冲（供 AI 分析） | `Record()` / `Drain()` |
| `RpcAiAnalyzer` | 类 | AI 分析编排（异步） | `MaybeAnalyze()` / `DrainPending()` |
| `RpcAiClient` | 类 | AI HTTP 客户端 | `AnalyzeAsync()` |
| `ConfigHotReloader` | 类 | 配置文件热重载 | `Tick()` |
| `AceUiRoot` | 静态类 | 画布创建 + 帧调度（帧去重） | `DriveFrame()` |
| `MonitorPanel` | 静态类 | 右上角监控面板 | `EnsureBuilt()` / `Tick()` |
| `NotificationPanel` | 静态类 | 右下角通知卡片 | `Show()` / `Tick()` |
| `SettingsWindow` | 静态类 | 游戏内设置界面 | `EnsureBuilt()` / `Tick()` |
| `DesktopSplash` | 静态类 | 桌面右下角启动动画（Win32 原生窗口） | `Show()` |

## 2. 依赖关系

```
                    AntiCheatPlugin
                          │ 创建并注入
                          ▼
   ┌──────────────── AntiCheatRuntime ────────────────┐
   │  持有：Config / Log / Tracker / Analyzer /        │
   │        Verdicts / Scanner / Recorder /            │
   │        AiAnalyzer / HotReloader / RpcFlood        │
   └───┬──────────────┬───────────────┬───────────────┘
       │              │               │
       ▼              ▼               ▼
  PlayerTracker  BehaviorAnalyzer  VerdictEngine
       ▲              ▲               ▲
       │              │               │
       └──────────────┴───────────────┘
                      │ 被调用
        ┌─────────────┴──────────────┐
        ▼                            ▼
   Patches（补丁层）            UI（界面层）
   读取 Config / 提交证据        读取 Verdicts / ScanReport

   所有对游戏对象的访问都必须经过 GameBridge
```

**分层原则**：

- `Core/` 内的算法**不直接引用游戏类型**（只用 `GameVec2` 等纯逻辑类型），
  以便脱离游戏环境推理与测试；
- 一切 il2cpp 访问集中在 `GameBridge`，便于游戏更新后单点修复；
- `UI/` 只读取运行时状态，不参与判定。

## 3. 数据流一：每帧循环

帧驱动由 **三个冗余入口**共同触发（任一可用即可）：

```
Canvas.SendWillRenderCanvases  ─┐
HudManager.Update              ─┼──► FrameDriver.Drive()
SplashManager.Update           ─┘         │
                                          ▼
                              AceUiRoot.DriveFrame()
                                 （Time.frameCount 去重，同帧只跑一次）
                                          │
              ┌───────────────────────────┼───────────────────────────┐
              ▼                           ▼                           ▼
   AntiCheatRuntime.Tick()      MonitorPanel.EnsureBuilt/Tick   SettingsWindow.Tick
              │                NotificationPanel.EnsureBuilt/Tick
              ▼
   ┌──────────────────────────────────────────────────┐
   │ 1. HotReloader.Tick()       每 0.5s 检查配置文件   │
   │ 2. 对局边沿检测（进入/退出）                       │
   │ 3. 会议边沿检测（开始/结束）                       │
   │ 4. 采样：SampleAllPlayers()  每 SampleInterval 秒  │
   │ 5. Verdicts.Tick()           空实现，维持契约      │
   │ 6. DrainAiResults()          回主线程的 AI 产物    │
   │ 7. CheckRiskLevelChanges()   每 0.2s 巡检并弹通知  │
   └──────────────────────────────────────────────────┘
```

> **性能要点**：面板刷新（0.2s）与风险巡检（0.2s）都已节流。
> 早期版本这两者每帧执行，会持续产生列表与字符串分配，是掉帧的主因。

### 采样环节（`SampleAllPlayers`）

对每个玩家：

1. 取 `GameBridge` 的各项状态，构造 `PlayerSnapshot`；
2. `track.Push(snapshot)` —— 计算与上一帧的位移 `DeltaDistance` 与时间差 `DeltaTime`；
3. 清空复用的 `EvidenceBuffer`；
4. 调用 `Analyzer.AnalyzeMovement(...)`，会议中额外调用 `AnalyzeMeetingMovement(...)`；
5. 把产出逐条 `Verdicts.Submit(v, now)`；
6. 调用 `AiAnalyzer.MaybeAnalyze(verdict)` 判断是否需要送 AI。

## 4. 数据流二：一次击杀（事件层）

```
PlayerControl.MurderPlayer 被调用
        │
        ▼
MurderPlayerPatch.Postfix(__instance, __args)
        │  1. 从 __args 里找 PlayerControl（受害者）
        │  2. 取击杀距离设置、击杀冷却
        ▼
AntiCheatRuntime.Analyzer.AnalyzeKill(killer, victim, now, dist, cd, buffer)
        │  产出：非内鬼击杀 / 超距击杀 / 冷却绕过
        ▼
foreach (v in buffer) AntiCheatRuntime.Submit(v)
        ▼
VerdictEngine.Submit(violation, now)
        │  1. 0.25s 同规则去重
        │  2. PlayerVerdict.AddEvidence(v)
        │  3. Evaluate(verdict, now)
        ▼
   ┌────────────────────────────────────────────┐
   │ 未警告过 → 记日志 + PlayerWarned 事件       │
   │ 未处置过 且 等级 ≥ HighRisk 且 允许自动踢人 │
   │        → KickRequested 事件                 │
   └────────────────────────────────────────────┘
        ▼
AntiCheatRuntime.HandleKickRequested(verdict)
        │  PlayerId → ClientId
        ▼
GameBridge.KickPlayer(clientId)   ← 内部再校验一次 IsHost
        ▼
AmongUsClient.Instance.KickPlayer(clientId, ban)
```

同时，这条击杀也会被喂给 `RpcEventRecorder`，供后续 AI 分析使用：

```
AntiCheatRuntime.Recorder.Record(killerId, "MurderPlayer", cooldown, distance)
        ▼
RpcEventRecorder 的每玩家环形缓冲（容量 32，超出覆盖最旧）
```

## 5. 数据流三：静态扫描

静态扫描**只在进入对局时执行一次**（`OnRoundEntered`），而不是启动时——
此时插件已全部加载完毕，且不拖慢游戏启动。

```
AntiCheatRuntime.OnRoundEntered(now)
        │ 若 Config.EnableStaticScan
        ▼
ModScanner.Scan()
        │  1. CollectLoadedPlugins()  从 IL2CPPChainloader.Instance.Plugins 取插件表
        │  2. 逐个 ClassifyPlugin()
        ▼
   ┌──────────────────────────────────────────────────────┐
   │ 分类优先级：                                          │
   │   ① 用户白名单（GUID / 名称 / 路径）  → TrustedPlugins │
   │   ② 内置默认信任（玩法/工具模组）      → TrustedPlugins │
   │   ③ 黑名单匹配（GUID→名称→类型名→字符串）→ Violations  │
   │   ④ 灰名单匹配                          → GrayPlugins  │
   │   ⑤ 未收录                              → 仅登记      │
   └──────────────────────────────────────────────────────┘
        ▼
ScanReport（AllPlugins / TrustedPlugins / GrayPlugins / Violations / Errors）
        │
        ├──► AntiCheatRuntime.ScanReport = report   （供监控面板展示）
        └──► Verdicts.SubmitAll(report.Violations)  （全局证据，PlayerId = -1）
```

黑名单的深度匹配会**读取插件文件内容**（上限 16 MB），同时按 UTF-8 与 UTF-16LE
两种视角搜索标记——后者用于识别被混淆但内部字符串仍为宽字符的插件。

## 6. 数据流四：AI 二次研判（异步）

```
AntiCheatRuntime.SampleAllPlayers()  （主线程）
        ▼
RpcAiAnalyzer.MaybeAnalyze(verdict)
        │ 门槛：EvidenceCount ≥ AiMinHitsToTrigger
        │       且不在 AiCooldownSeconds 冷却内
        │       且未被 AI 确认过
        │       且配置完整（开关开 + 密钥已填）
        ▼
RpcEventRecorder.Drain(playerId)  → RpcEvent[]
        ▼
CaptureSnapshot()  （主线程抓取玩家/对局上下文）
        ▼
Task.Run(RunAnalysisAsync)  ────────► 后台线程
        │                                   │
        │                                   ▼
        │                      RpcAiClient.AnalyzeAsync(systemPrompt, userPrompt)
        │                      HTTP POST → DeepSeek /chat/completions
        │                                   │
        │              ┌────────────────────┴────────────────────┐
        │              ▼                                         ▼
        │        解析失败/超时                              解析出结构化判定
        │        → 写 state.Summary（界面可见）             → _pendingViolations.Enqueue
        │                                                  → verdict.AiConfirmed = true
        ▼
主线程 DrainPending(VerdictEngine)  → Verdicts.Submit(...)
```

> AI 只是**辅助**：失败时静默降级，规则引擎继续工作；
> 它不替代任何本地检测，最终判定权仍在规则引擎。

## 7. 启动与卸载时序

```
BepInEx 加载 AmongUsAntiCheat.dll
        ▼
AntiCheatPlugin.Load()
   ├─ LogSource = Log
   ├─ new AntiCheatConfig(Config)        创建/读取配置文件
   ├─ new PlayerTracker / BehaviorAnalyzer / VerdictEngine / ModScanner
   ├─ AntiCheatRuntime.Initialize(...)   建 Recorder / AiAnalyzer / RpcFlood / HotReloader
   ├─ AntiCheatRuntime.OnLoaded()        接线 Analyzer.IsInsideWall、订阅 KickRequested
   └─ ApplyPatches()                     逐个挂载 3 帧驱动 + 5 检测补丁
        ▼
（游戏运行，帧驱动开始调用 DriveFrame）

BepInEx 卸载
        ▼
AntiCheatPlugin.Unload()
   ├─ _harmony.UnpatchSelf()
   ├─ SnapToPatch.ResetStats()
   └─ AntiCheatRuntime.Shutdown()        退订事件
```

**装配顺序有讲究**：必须先建好模块并接线，最后才挂补丁。
补丁一旦挂上，游戏随时可能触发回调；若此时检测循环未就绪，回调会拿到 `null` 而丢事件。
