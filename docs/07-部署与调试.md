## 2. 架构说明（重要）

本插件的程序集标记为 **AnyCPU**：

```
Platforms      = AnyCPU;x86;x64
PlatformTarget = AnyCPU
Prefer32Bit    = false
```

验证方式（产物 `COR flags` 应为 `0x1`，即 `ILONLY` 且 **`32BITREQUIRED = false`**）：

```
COR flags: 0x1 | ILONLY: True | 32BITREQUIRED: False
```

**为什么必须是 AnyCPU**：如果程序集被标记为 `x86`（`32BITREQUIRED`），
它在 64 位游戏进程里会直接抛出 `BadImageFormatException` 而加载失败。
AnyCPU 让同一份 dll 同时适用于两种架构，游戏更新到 64 位后无需重新编译。

### 架构相关的代码约定

新增 P/Invoke 结构体时**不要硬编码 `Size`**。Win32 结构体的尺寸随架构变化，例如
`PAINTSTRUCT`：x86 = 64 字节，x64 = **72 字节**。硬编码 `Size = 64`
在 64 位下会导致 `BeginPaint` 越界写 8 字节，踩坏栈上相邻数据 → 随机崩溃。

正确写法是让字段自然排布，由 `Marshal` 推导尺寸：

```csharp
[StructLayout(LayoutKind.Sequential)]
private struct PAINTSTRUCT
{
    public IntPtr hdc;        // x86=4 / x64=8，由 IntPtr 自适应
    public int fErase;
    public RECT rcPaint;
    public int fRestore;
    public int fIncUpdate;
    private int _r0, _r1, _r2, _r3, _r4, _r5, _r6, _r7;  // rgbReserved[32]
}
```

## 3. 构建

### 3.1 前置条件

- .NET SDK 6.0 或更高（实测 8.0.405 可正常编译 net6.0 目标）
- 已安装游戏与 BepInEx 6（编译时需要引用游戏与 BepInEx 的程序集）

### 3.2 游戏路径

`csproj` 中的默认路径：

```xml
<GameDir Condition="'$(GameDir)' == ''">E:\STEAM\steamapps\common\Among Us</GameDir>
```

游戏不在该路径时，用参数覆盖：

```bash
dotnet build -c Release -p:GameDir="D:\Steam\steamapps\common\Among Us"
```

### 3.3 编译命令

```bash
# 常规编译（编译成功后自动拷贝到 BepInEx/plugins）
dotnet build -c Release

# 只编译、不部署
dotnet build -c Release -p:AutoDeploy=false
```

产物路径：`bin/Release/AmongUsAntiCheat.dll`
（`AppendTargetFrameworkToOutputPath=false`，因此**没有** `net6.0` 子目录）

### 3.4 编译期引用的程序集

| 来源 | 程序集 |
|---|---|
| `BepInEx/core` | BepInEx.Core、BepInEx.Unity.IL2CPP、BepInEx.Unity.Common、Il2CppInterop.Runtime / Common / HarmonySupport、0Harmony、MonoMod.RuntimeDetour、SemanticVersioning |
| `BepInEx/interop` | Assembly-CSharp、Assembly-CSharp-firstpass、Il2Cppmscorlib、Il2CppSystem、Il2CppSystem.Core |
| `BepInEx/interop`（Unity 模块） | CoreModule、Physics2DModule、IMGUIModule、InputLegacyModule、TextRenderingModule、UIModule、UI、AudioModule |

> Unity 程序集必须引用 **interop 目录**里的那一套，而不是 `unity-libs`。
> interop 里的 `UnityEngine` 是 Il2CppInterop 生成的，其 `MonoBehaviour` 继承链顶端是
> `Il2CppObjectBase`；`unity-libs` 里是另一套参考程序集，类型不兼容，
> 会导致 `AddComponent<T>` 等泛型约束编译失败。

## 4. 部署

### 4.1 手动部署

```
<游戏目录>/BepInEx/plugins/AmongUsAntiCheat.dll
```

### 4.2 自动部署

`csproj` 内置了部署目标，`AutoDeploy` 默认为 `true`：

```xml
<Target Name="DeployToPlugins" AfterTargets="Build"
        Condition="'$(AutoDeploy)' == 'true' And Exists('$(BepInExPlugins)')">
```

编译成功后输出 `[AntiCheat] 已部署 -> <路径>`。目标目录不存在时自动跳过。

### 4.3 卸载

直接删除 `BepInEx/plugins/AmongUsAntiCheat.dll` 即可。
配置文件（`BepInEx/config/apex.cheat.ender.cfg`）不会被删除，需要时手动清理。

## 6. 调试

### 6.1 开启详细日志

配置 `开哪些检测 / 输出详细日志 = true` 后，每次位置采样都会输出一行：

```
[运动采样] <玩家名>(<id>) 位移=1.234 dt=0.100 速度=12.34/2.50
```

配合 `[规则命中]` 行可以完整还原判定依据。**正常游玩请关闭**，日志增长很快。

### 6.2 关键日志前缀

| 前缀 | 来源 | 含义 |
|---|---|---|
| `[初始化]` / `[反作弊]` | `AntiCheatPlugin` / `AntiCheatRuntime` | 启动与对局生命周期 |
| `[补丁]` | `AntiCheatPlugin.TryPatch` | 每个补丁的挂载结果（成功 / 跳过原因） |
| `[静态扫描]` | `ModScanner` | 插件扫描结果 |
| `[规则命中]` | `VerdictEngine.Submit` | 证据产生 |
| `[判定]` | `VerdictEngine` | 等级结论 |
| `[处置]` | `AntiCheatRuntime.HandleKickRequested` | 踢人动作与结果 |
| `[RPC洪水]` | `RpcFloodGuard` | 洪水拦截 |
| `[配置]` | `ConfigHotReloader` | 热重载变更 |
| `[AI]` | `RpcAiAnalyzer` | AI 分析结果或失败原因 |
| `[UI]` | `AceUiRoot` | 画布创建与帧刷新异常 |

### 6.3 补丁挂载自检

启动后检查日志中的 `[补丁]` 行，应能看到 8 条挂载记录：

```
[补丁] 帧驱动(Canvas) 已挂载 -> Canvas.SendWillRenderCanvases(0 参数, Postfix)
[补丁] 帧驱动(HudManager) 已挂载 -> ...
[补丁] 帧驱动(SplashManager) 已挂载 -> ...
[补丁] 击杀 已挂载 -> PlayerControl.MurderPlayer(N 参数, Postfix)
[补丁] 任务完成 已挂载 -> ...
[补丁] 通风管 已挂载 -> ...
[补丁] 位置强制同步 已挂载 -> ...
[补丁] RPC 洪水防护 已挂载 -> PlayerControl.HandleRpc(N 参数, Prefix)
```

若出现「在当前游戏版本中未找到目标方法，已跳过该检测」，
说明该检测在当前游戏版本下不可用——**其余检测不受影响**（这是刻意的容错设计）。

## 7. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 游戏里完全看不到插件痕迹 | 插件没被加载 | 检查 `LogOutput.log` 是否有 `Apex Cheat Ender v...` 启动横幅 |
| 加载时报 `BadImageFormatException` | 程序集架构与进程不匹配 | 确认产物为 AnyCPU（`COR flags = 0x1`） |
| 面板不出现 | ①「检查动作是否合法」被关闭；② 启动 4.6 秒内；③ `显示右上角监控面板 = false` | 逐项检查 |
| 面板出现但文字是方块 | 系统中文字体缺失 | `UiBuilder.LoadFont` 已尝试 Microsoft YaHei / SimHei / SimSun，均失败时退回内置字体（英文可显示） |
| 桌面启动动画不出现 | `显示开机启动动画 = false`，或非 Windows 平台 | 检查配置 |
| 改了配置没生效 | 文件被写坏或路径不对 | 看日志 `[配置]` 行；确认改的是 `BepInEx/config/apex.cheat.ender.cfg` |
| 装了就掉帧 | 采样间隔过小 | 调大 `看位置的间隔（秒）` |
| 某检测完全不工作 | 该补丁在当前版本未挂载 | 看日志 `[补丁]` 行的跳过原因 |
| 日志刷屏 | `输出详细日志 = true` | 关掉 |
| AI 一直「分析失败」 | 密钥错误 / 网络不通 / 超时 | 看日志 `[AI]` 行；确认密钥已填且能直连供应商 |

## 8. 已知的环境现象（不是插件 Bug）

| 现象 | 说明 |
|---|---|
| `Class::Init signatures have been exhausted, using a substitute!` | Il2CppInterop 对较新游戏的**固有限制提示**。插件正常工作即可忽略。 |
| 游戏大更新后出现 `Class_FromIl2CppType_Hook` 空引用 | 通常应**升级 BepInEx**，而不是改插件代码。 |
| 启动瞬间有若干 `unsupported return type` 之类警告 | 与 il2cpp 类型桥接有关；只要插件正常加载即可忽略。 |

| 项 | 状态 |
|---|---|
| 单元测试 | **有**（`tests/`，零依赖控制台 runner，9 个用例）。覆盖 `GameVec2` / `PlayerTrack` / `PlayerTracker` / `Violation` / `PlayerVerdict`。**未覆盖** `BehaviorAnalyzer` 的检测算法（它依赖配置对象，需要先做可测性改造）。 |
| CI / 自动化构建 | **有**（`.github/workflows/tests.yml`）。**只跑测试**——插件本体编译需要游戏目录的 interop 程序集，CI 上拿不到。 |
| 代码签名 / 发布流程 | **无**。Release 手动发布（可用 `gh-release.py` 脚本）。 |

> 若后续要扩大测试覆盖，建议从 `BehaviorAnalyzer` 的 `Analyze*` 系列入手——
> 它们是纯函数式的（输入轨迹与阈值，输出证据列表），最容易覆盖边界条件。
> 需要先把它对 `AntiCheatConfig` 的依赖抽成接口或参数包，才能脱离 BepInEx 编译。
