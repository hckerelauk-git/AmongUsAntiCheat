# 06 · 常见误判场景与处理

误报是反作弊插件最大的风险：**冤判一个正常玩家的代价，远高于漏掉一个作弊者**。
本文汇总已知的误判来源、成因与处置办法。

---

## 0. 先分清三类「误判」

看到异常标记时，先判断属于哪一类，处置方式完全不同：

| 类型 | 特征 | 处置方向 |
|---|---|---|
| **真误判** | 判定逻辑与游戏规则不符（如把 Viper 当内鬼判） | 修代码或改配置 |
| **网络问题** | 玩家延迟高、丢包、重连，导致位置/时间数据失真 | 放宽阈值 |
| **游戏 Bug** | 地图碰撞、角色机制导致的异常，非玩家主观作弊 | 关掉对应检测 |

## 1. 已修复的历史误判（了解即可，不必再调参）

### 1.1 Viper 等角色被误判为「非内鬼用通风管」

| 项 | 内容 |
|---|---|
| **现象** | 某玩家一进管道就被判 `Critical` 并可能被踢 |
| **成因** | 早期用 `IsImpostor`（阵营）判断通风资格。但本版游戏有 **Viper**——船员阵营、`Role.CanVent = true`。躲猫猫的 Seeker 同理。 |
| **修复** | 改用 `Role.CanVent`（`GameBridge.TryGetCanVent`），并新增 `PlayerSnapshot.CanVent / RoleKnown`。角色信息不可用时**一律放行**。 |
| **代码** | `BehaviorAnalyzer.AnalyzeVentUse` |

> 这是最典型的「用阵营代替能力」错误，新增任何角色相关检测时都要避免。

### 1.2 游戏卡顿导致瞬移误判

| 项 | 内容 |
|---|---|
| **现象** | 网络波动或掉帧时，正常玩家被判瞬移 |
| **成因** | 早期瞬移判定**只看位移距离，不看耗时**。一次 1 秒的卡顿，正常玩家也能位移好几个单位。 |
| **修复** | 增加第二条件：隐含速度 = 位移 / 时间差 必须 > `允许上限 × 3`。 |
| **代码** | `BehaviorAnalyzer.AnalyzeMovement`，常量 `TeleportSpeedFactor = 3f` |

### 1.3 性能问题被误认为「卡顿是反作弊造成的」

| 项 | 内容 |
|---|---|
| **现象** | 装了插件就掉帧 |
| **成因** | 监控面板与风险巡检**每帧**全量遍历玩家、`new List`、`new StringBuilder`、拼字符串，持续制造 GC 压力。 |
| **修复** | 面板刷新与风险巡检节流至 **5 Hz（0.2s）**，并复用列表与字符串缓冲。 |

## 2. 仍可能发生的误判与处置

### 2.1 超速（SpeedHack）误报

| 项 | 内容 |
|---|---|
| **成因** | 网络抖动使相邻两次采样的时间差异常小，瞬时速度被放大；或玩家确实在使用加速类玩法模组。 |
| **缓解** | 已有三道闸门（豁免窗口 / 抖动容差 / 连续命中计数）。 |
| **处置** | 调大 `允许比正常快几倍`（1.6 → 2.0）；或调大 `超速几次才记下来`。 |

### 2.2 击杀距离（KillTooFar）误报

| 项 | 内容 |
|---|---|
| **成因** | 击杀判定读取的是**最近一次采样的位置**，最多滞后一个采样周期（默认 0.1 秒）。高速移动时误差被放大。 |
| **处置** | 调大 `隔多远能砍人（额外放宽）`。 |

### 2.3 击杀冷却（KillCooldownBypass）误报

| 项 | 内容 |
|---|---|
| **成因** | 一次击杀可能经由多条路径触发 `MurderPlayer`，第二次调用会看到间隔 ≈ 0。判定层有 0.25s 去重，但仍可能漏网。 |
| **处置** | 调大 `冷却能提前多久（秒）`。 |

### 2.4 远程任务（RemoteTask）误报

| 项 | 内容 |
|---|---|
| **成因** | ① 任务点解析失败时，代码退回使用玩家当前位置，反而不会误报；但解析到**错误任务点**时会；② 多步任务（如「启动反应堆」需两处操作）的判定位置与实际不符；③ 地图边缘碰撞导致玩家被推开。 |
| **处置** | 调大 `隔多远能交任务（额外放宽）`（2.0 → 4.0）。 |

### 2.5 任务速度（TaskTooFast）误报

| 项 | 内容 |
|---|---|
| **成因** | 用两任务点的**直线距离**估算最短耗时，而玩家实际走的是折线路径。若两个任务点恰好在直线可达位置，正常玩家也可能「快于下限」。 |
| **处置** | 调大 `做任务允许快几倍`（1.5 → 2.5）。 |

### 2.6 会议位移（MoveDuringMeeting）误报

| 项 | 内容 |
|---|---|
| **成因** | 会议开始/结束时所有玩家会被重新排布到会议桌。代码对此时刻打了**豁免标记**，但若采样恰好落在标记之前，仍可能被捕获。 |
| **处置** | 调大 `会议时允许走多远`（0.75 → 1.5）。 |

### 2.7 穿墙（WallClip）误报

| 项 | 内容 |
|---|---|
| **成因** | ① 地图 Bug 把玩家挤出碰撞体；② 网络延迟导致坐标瞬时落在墙体内部；③ 某些玩法模组会改变地图碰撞。 |
| **处置** | **保持该项关闭**（默认即关闭）。需要认准作弊请依赖静态扫描与事件检测。 |

### 2.8 RPC 洪水误报

| 项 | 内容 |
|---|---|
| **成因** | 网络差的房间会产生大量重传；观战/录制类模组也会增加流量。 |
| **处置** | 调大 `10 秒内最多几次数据包`（60 → 100+）。 |

### 2.9 位置强制同步（SnapTo）误报

| 项 | 内容 |
|---|---|
| **成因** | 玩家网络重连、极端抖动时游戏会主动 `RpcSnapTo` 重同步。 |
| **处置** | 调大 `10 秒内最多几次强制同步`；或直接关闭 `抓瞬移式位置同步`。 |

### 2.10 玩法模组被误判为作弊插件

| 项 | 内容 |
|---|---|
| **成因** | 未收录的玩法模组名里带敏感词（Menu / Unlock / Cheat）时可能命中黑名单的名称片段规则。 |
| **处置** | 在 `信任的插件 GUID` 或 `信任的插件名` 里加入该模组。 |

> `CheatSignatureDb.DefaultTrustedMarkers` 已内置常见玩法模组
> （TheOtherRoles / TownOfUs / TownOfUs / Reactor / BetterAmongUs 等），
> 但无法覆盖全部。

### 2.11 角色信息不可用导致的降级行为

| 项 | 内容 |
|---|---|
| **现象** | 某些时刻检测「失效」（不报也不拦） |
| **成因** | 角色对象尚未创建（加载期）或游戏更新导致字段改名时，`TryGetCanVent` 返回 `false`，通风管判定**主动放行**。这是刻意的保守设计。 |
| **处置** | 属于预期行为，无需处理。若长期如此，检查 BepInEx / 游戏版本是否匹配。 |

## 3. 调参速查表

| 看到的误报 | 先调这个 | 方向 |
|---|---|---|
| 瞬移 | `一下挪多远算瞬移` | 调大 |
| 超速 | `允许比正常快几倍` | 调大 |
| 超速（偶发） | `超速几次才记下来` | 调大 |
| 超距击杀 | `隔多远能砍人（额外放宽）` | 调大 |
| 冷却绕过 | `冷却能提前多久（秒）` | 调大 |
| 远程任务 | `隔多远能交任务（额外放宽）` | 调大 |
| 任务速度异常 | `做任务允许快几倍` | 调大 |
| 会议位移 | `会议时允许走多远` | 调大 |
| 穿墙 | `检测穿墙` | 关掉 |
| RPC 洪水 | `10 秒内最多几次数据包` | 调大 |
| 强制同步 | `10 秒内最多几次强制同步` | 调大 |
| 玩法模组被误判 | `信任的插件名` | 加入白名单 |
| 开局就误报 | `开局后先不管几秒` | 调大 |
| 通用（整体太敏感） | `看位置的间隔（秒）` | 调大（0.1 → 0.2） |

## 4. 排查流程

发现疑似误判时，按以下顺序定位：

```
① 打开「输出详细日志」
   └─ 复现一次，在 BepInEx/LogOutput.log 搜索 [运动采样] / [规则命中]
      → 拿到具体数值（位移、速度、阈值）

② 对照上表调参
   └─ 改完保存即生效（热重载 0.5s），不必重启游戏

③ 若调参无效，判断是否为「真误判」
   └─ 若判定逻辑与游戏规则不符 → 属于代码问题，需修改检测逻辑

④ 用「信任的插件名 / GUID」排除模组干扰

⑤ 最后手段：关闭对应检测
   └─ 关「检查动作是否合法」会跳过全部补丁，是最粗的开关
```

---

## 5. 设计层面的降误报原则

新增任何检测时，请遵守这些既有原则：

1. **宁可漏报，不可冤判**。数据不可用时返回保守值、主动放行。
2. **判定用能力，不用阵营**。参考 Viper 的教训。
3. **单次异常不成立**。必须配合连续计数或时间窗口。
4. **豁免窗口优先**。回合开始、会议前后、通风管、重同步都要打豁免标记。
5. **给不出数值依据的判定不要写**。每条证据都必须能回答「为什么判他」。
