# 01 · 检测目标

本文说明 Apex Cheat Ender 到底在防什么、把行为判定到什么程度、以及**明确不防什么**。

---

## 1. 定位与作用域

Apex Cheat Ender 是一个**客户端反作弊插件**，运行在每个安装了它的玩家进程内。它的行为随身份不同而不同：

| 身份 | 能力 |
|---|---|
| 自己是房主（Host） | 完整检测 + **可以丢弃 RPC** + 可以踢出玩家 |
| 自己是普通成员 | 只检测、只记录、只提示；**绝不丢弃任何 RPC，也不踢人** |

> 这条边界是硬性设计约束。丢弃与踢出的唯一判定入口是 `GameBridge.IsHost`，
> 任何新增的拦截逻辑都必须先过这一关，否则会破坏非房主玩家的对局同步。

### 客户端反作弊的固有天花板

作弊者可以在**自己的机器上**不装、禁用或篡改本插件，因此客户端方案无法做到「绝对防护」。
Apex Cheat Ender 的价值在于：**提高作弊成本**，并让房主在事后有可追溯的证据链。
真正彻底的防护需要服务端权威校验，这不在本插件范围内。

---

## 2. 检测目标分四类

Apex Cheat Ender 把「什么算作弊」拆成四类，每类的证据置信度不同，处理方式也不同。

### 2.1 静态证据 —— 「作弊软件确实存在」

**目标**：作弊工具必须先被注入进程才能生效，而注入必然在 BepInEx 的插件表里留下痕迹。

**检测对象**：已加载的 BepInEx 插件（GUID、插件名、程序集路径、程序集内部类型名与字符串）。

**为什么置信度最高**：这类证据是「存在性」判断，不依赖运行时行为推断，因此**几乎不会误报**。

**命中后**：产生 `ViolationKind.KnownCheatPlugin` 或 `UnknownPlugin`，归属为**全局证据**
（`PlayerId = -1`，因为静态扫描无法把它关联到某个具体的游戏内玩家）。

### 2.2 行为异常 —— 「物理上做不到的动作」

**目标**：正常玩家的移动受地图、速度、碰撞约束。超出约束的轨迹即异常。

**检测对象**：

| 检测项 | 判定依据 | 严重度 |
|---|---|---|
| 瞬移 | 单次采样位移 ≥ `一下挪多远算瞬移`，**且**隐含速度 > 允许上限 × 3 | 首次 `High`，重复 `Critical` |
| 持续超速 | 连续 N 次采样的瞬时速度 > 允许上限 × 倍率 | `High` |
| 穿墙 | 玩家坐标落在 `Ship` 层碰撞体内部（默认关闭） | `Medium` |
| 会议位移 | 会议期间位移 > `会议时允许走多远` | `High` |

### 2.3 事件非法 —— 「动作在当前状态下不该发生」

**目标**：每个关键动作（击杀、做任务、钻管道）都有前置条件。前置条件不满足即为非法。

| 检测项 | 判定依据 | 严重度 |
|---|---|---|
| 非内鬼击杀 | 击杀者的 `Role.IsImpostor == false` | `Critical` |
| 超距击杀 | 击杀者与被击杀者距离 > 设置距离 + 容差 | `High` |
| 击杀冷却绕过 | 两次击杀间隔 < 角色冷却 − 容差 | `High` |
| 远程提交任务 | 提交时玩家位置距任务点 > 容差 | `High` |
| 任务速度异常 | 两任务点间耗时 < 直线距离 / 最大速度 / 倍率 | 首次 `Medium`，重复 `Critical` |
| 无通风能力者用通风管 | `Role.CanVent == false` | `Critical` |
| 远程使用通风管 | 与通风管距离 > 容差 | `High` |

> **通风管判定必须用 `Role.CanVent` 而不是 `IsImpostor`**。本版游戏存在 Viper 这类
> 「船员阵营但被允许钻管道」的角色，用阵营判断会把它误判为 `Critical` 并直接踢人。

### 2.4 网络异常 —— 「协议层的不正常流量」

**目标**：异常流量会拖垮整房，也可能是在用协议漏洞作弊。

| 检测项 | 判定依据 | 结果 |
|---|---|---|
| RPC 洪水 | 单个 OwnerId 在 10 秒内 RPC 数 > `10 秒内最多几次数据包` | 房主丢弃该 RPC，并熔断 1~2.5 秒 |
| 位置强制同步高频 | 单个玩家 10 秒内 `RpcSnapTo` 次数 ≥ 阈值 | 提交 `Teleport` 证据 |

## 3. 判定分级：从「证据」到「结论」

这是本插件最核心的语义，务必分清两个概念：

- **`Severity`（严重度）**：描述**单条证据**的确信程度，是**输入**。
- **`RiskLevel`（风险等级）**：对某个玩家**综合判定后的结论**，是**输出**。

### Severity 四档

| 值 | 含义 |
|---|---|
| `Low` | 提示级。单独出现不构成判定，仅记录。 |
| `Medium` | 可疑级。可能是网络抖动或误报。 |
| `High` | 高度可疑。需要多次确认或配合其他证据。 |
| `Critical` | 确定级。物理上不可能发生，可直接处置。 |

### RiskLevel 四档与推导规则

判定**不看分数**，只看规则命中情况：

```
命中条数 == 0                    → Normal     （正常）
AI 已确认                        → Confirmed  （已确认）
存在 Critical 命中               → HighRisk   （高危）
其余命中（存在但无 Critical）     → Suspicious （已命中，待处置）
```

> 界面上的任何标记都必须依据 `RiskLevel`，不允许直接拿 `Severity` 或分数打标记，
> 否则「只是被追踪过、零命中」的玩家也会被标红，属于无依据标记。

---

## 4. 明确不防的目标

以下内容**不在**本插件职责范围内，也不应期望它能处理：

1. **房主自己作弊**。房主拥有房间权威，插件无法约束房主。
2. **作弊者不装本插件**。见「客户端反作弊的固有天花板」。
3. **服务端可验证的作弊**（如改包伪造大厅信息）。这需要服务端权威校验。
4. **队友配合 / 语音串通**等信息层作弊。Apex Cheat Ender 只处理程序可判定的行为。
5. **游戏本体 Bug 造成的异常**。例如某些地图 Bug 会让玩家被挤出碰撞体，
   这类会被 `穿墙` 检测看到——这也是该检测**默认关闭**的原因之一。
