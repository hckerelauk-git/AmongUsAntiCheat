# 05 · 对外接口与返回值

本文列出插件内部各层之间的契约。所有接口的设计前提是：
**游戏更新或数据缺失时，宁可返回保守值，也不抛异常、不崩进程。**

---

## 1. GameBridge —— 游戏 API 桥接层

**这是唯一允许访问 il2cpp 对象的入口。** 任何模块需要读取游戏状态，都必须经过它。
每个方法都做了「多路径降级 + 异常吞掉」，因此调用方**不需要判空、不需要 try/catch**。

### 1.1 对局状态（只读属性）

| 成员 | 返回类型 | 失败时的值 | 说明 |
|---|---|---|---|
| `IsInGame` | `bool` | `false` | `AmongUsClient.Instance.IsGameStarted && ShipStatus.Instance != null` |
| `IsInMeeting` | `bool` | `false` | `MeetingHud.Instance != null` |
| `IsHost` | `bool` | `false` | `AmongUsClient.Instance.AmHost`。**丢弃与踢人的唯一判定入口** |
| `LocalClientId` | `int` | `-1` | 本地玩家的 ClientId |

### 1.2 玩家查询

| 方法 | 返回类型 | 失败时的值 | 说明 |
|---|---|---|---|
| `GetPlayers()` | `List<PlayerControl>` | 空列表（**永不为 null**） | 当前全部玩家 |
| `GetLocalPlayer()` | `PlayerControl` | `null` | 本地玩家 |
| `GetPlayerId(player)` | `int` | `-1` | 玩家 Id（IL2CPP 下 `PlayerId` 是 byte，统一转 int） |
| `GetPlayerName(player)` | `string` | `"?"` | 已清洗 BBCode / 富文本标签 |
| `GetPlayerById(playerId)` | `PlayerControl` | `null` | 按 PlayerId 反查 |
| `GetClientIdByPlayerId(playerId)` | `int` | `-1` | 踢人前需要它把 PlayerId 转成 ClientId |

### 1.3 玩家状态

| 方法 | 返回类型 | 失败时的值 | 说明 |
|---|---|---|---|
| `GetPosition(player)` | `GameVec2` | `GameVec2.Zero` | 世界坐标 |
| `IsDead(player)` | `bool` | `true` | 失败时**按已死亡处理**（更保守，不会误判活人动作） |
| `IsDisconnected(player)` | `bool` | `false` | |
| `IsInVent(player)` | `bool` | `false` | |
| `CanMove(player)` | `bool` | `true` | |
| `IsImpostor(player)` | `bool` | `false` | 首选 `Role.IsImpostor`，降级按 `RoleType` 枚举 |
| `TryGetCanVent(player, out bool canVent)` | `bool` | 返回 `false` | **角色能力**。返回 `false` 表示角色信息不可用，此时 `canVent` 无意义 |

> `IsImpostor` 与 `TryGetCanVent` 的区别很关键：
> **阵营**（IsImpostor）与**能力**（CanVent）不是一回事。
> 本版游戏存在 Viper 这类「船员阵营但能钻管道」的角色，
> 判断通风管合法性必须用 `TryGetCanVent`。

### 1.4 游戏设置读取

| 方法 | 返回类型 | 失败时的值 | 说明 |
|---|---|---|---|
| `GetMaxAllowedSpeed(reference = null)` | `float` | `2.5`（基准速度） | 首选 `PlayerPhysics.TrueSpeed`；降级用 `PlayerSpeedMod × 2.5` |
| `GetAllowedKillDistance()` | `float` | `1.8`（中档） | 由 `KillDistance` 档位查表：`{1.0, 1.8, 2.5}` |
| `GetKillCooldown()` | `float` | `25` | 读 `KillCooldown` 选项 |

### 1.5 物理与处置

| 方法 | 返回类型 | 失败时的值 | 说明 |
|---|---|---|---|
| `IsInsideWall(point)` | `bool` | `false` | `Physics2D.OverlapPoint` 查 `Ship` 层。层不存在时返回 false（**禁用该检测**） |
| `InvalidateLayerCache()` | `void` | — | 场景切换后重置缓存的层掩码 |
| `KickPlayer(clientId, ban = false)` | `bool` | `false` | **内部会再校验一次 `IsHost`**；不是房主或目标是本人时直接返回 false |
| `GetTaskPosition(player, taskId)` | `GameVec2?` | `null` | 从玩家自己的 `myTasks` 列表查任务点坐标 |

## 2. Harmony 补丁契约

补丁通过**反射**挂载（`AntiCheatPlugin.TryPatch`），因此必须遵守固定命名与签名约定。

### 2.1 挂载约定

| 成员 | 要求 | 说明 |
|---|---|---|
| `TargetMethod` | `private static MethodBase` | 返回要挂载的方法；返回 `null` 表示「当前游戏版本找不到」，跳过而不报错 |
| `Prefix` | `private static bool` | **可选**。返回 `false` 可**阻止原方法执行**（用于拦截） |
| `Postfix` | `private static void` | **可选**。原方法执行后调用（用于观察） |

至少要实现 `Prefix` 与 `Postfix` 之一，否则该补丁类会被跳过并输出警告。

### 2.2 参数约定

补丁统一使用 Harmony 的注入参数：

| 参数名 | 类型 | 含义 |
|---|---|---|
| `__instance` | 目标实例类型 或 `object` | 被调用方法的实例 |
| `__args` | `object[]` | 原方法的**全部实参**，用于通用取参 |

**用 `__args` 而不是具名参数**是刻意的：Among Us 每个大版本都会给核心方法加参数
（例如 `MurderPlayer` 后来加了 `MurderResultFlags`），
按名取参会因签名变化而失效，按 `__args` 取类型则不会。

### 2.3 已挂载的补丁清单

| 补丁类 | 目标 | 类型 | 作用 |
|---|---|---|---|
| `CanvasFramePatch` | `UnityEngine.Canvas.SendWillRenderCanvases` | Postfix | 帧驱动（主入口） |
| `HudFramePatch` | `HudManager.Update` | Postfix | 帧驱动（大厅/对局） |
| `SplashFramePatch` | `SplashManager.Update` | Postfix | 帧驱动（启动阶段） |
| `MurderPlayerPatch` | `PlayerControl.MurderPlayer` | Postfix | 击杀检测 |
| `CompleteTaskPatch` | `PlayerControl.CompleteTask` | Postfix | 任务检测 |
| `VentEnterPatch` | `Vent.EnterVent` | Postfix | 通风管检测 |
| `SnapToPatch` | `CustomNetworkTransform.RpcSnapTo` | Postfix | 位置同步频率检测 |
| `RpcFloodPatches` | `PlayerControl.HandleRpc` | **Prefix** | RPC 洪水拦截（唯一可丢弃的补丁） |

> 帧驱动挂三个入口是**冗余设计**：任一入口在当前游戏版本可用即可，
> 且 `AceUiRoot.DriveFrame` 内部用 `Time.frameCount` 做了帧去重，
> 同帧被多个入口触发不会重复执行。

### 2.4 帧驱动入口的返回值语义

三个帧驱动补丁的 `Postfix` 均返回 `void`，不做拦截，仅调用 `FrameDriver.Drive()`。

`RpcFloodPatches.Prefix` 返回 `bool`：

```
true  → 放行（默认）
false → 丢弃该 RPC（仅在 blocked && GameBridge.IsHost 时返回）
```

## 3. 核心数据类型

### 3.1 `Violation` —— 系统内部流通的统一「货币」

```csharp
public sealed class Violation
{
    ViolationKind Kind;                        // 违规类型
    Severity      Severity;                    // 单条证据的确信程度
    int           PlayerId;                    // -1 表示全局证据（不归属具体玩家）
    string        PlayerName;
    float         Timestamp;                   // Time.time
    string        Detail;                      // 人类可读描述，直接进日志
    IReadOnlyDictionary<string,float> Metrics; // 结构化数值，供调参与申诉
    float         BaseWeight;                  // 由 Severity 推导（当前未被判定逻辑使用）
}
```

> `BaseWeight` 是分数模型的遗留字段，当前判定**不看分数**，因此它不参与任何决策。

### 3.2 `ViolationKind` —— 违规类型枚举

| 分组 | 取值 | 是否会被产生 |
|---|---|---|
| 静态 | `KnownCheatPlugin` | ✅ ModScanner 黑名单命中 |
| 静态 | `UnknownPlugin` | ✅ ModScanner 灰名单命中 |
| 静态 | `MemoryTamper` | ❌ 无产生点 |
| 行为 | `Teleport` | ✅ 瞬移 / SnapTo 高频 |
| 行为 | `SpeedHack` | ✅ 持续超速 |
| 行为 | `WallClip` | ✅ 穿墙（默认关闭） |
| 事件 | `KillTooFar` / `KillCooldownBypass` / `KillWhileNotImpostor` | ✅ 击杀检测 |
| 事件 | `TaskTooFast` / `RemoteTask` | ✅ 任务检测 |
| 事件 | `IllegalVent` | ✅ 通风管检测 |
| 事件 | `GhostAction` | ❌ 算法已写但无调用点 |
| 会议 | `MoveDuringMeeting` | ✅ 会议位移 |
| 会议 | `IllegalMeetingAction` | ❌ 无产生点 |
| 网络 | `InvalidRpc` | ⚠️ 仅作为 AI 结果无法映射时的兜底值 |
| 网络 | `StateDesync` | ❌ 无产生点 |

### 3.3 `Severity` 与 `RiskLevel`

```csharp
enum Severity  { Low, Medium, High, Critical }     // 输入：单条证据
enum RiskLevel { Normal, Suspicious, HighRisk, Confirmed }  // 输出：综合结论
```

推导规则（`PlayerVerdict.EvaluateLevel`）：

```
Evidence.Count == 0  → Normal
AiConfirmed          → Confirmed
CriticalCount > 0    → HighRisk
否则                  → Suspicious
```

### 3.4 `PlayerSnapshot` / `PlayerTrack`

`PlayerSnapshot` 是**值类型**（避免采样产生 GC 压力），字段：
`Time / Position / IsDead / InVent / IsImpostor / CanVent / RoleKnown / CanMove / InMeeting / DeltaDistance / DeltaTime`，
另有派生属性 `Speed`。

`PlayerTrack` 保存单玩家的 `Previous` / `Current` 快照、`History` 队列（容量 64）、
各类连续计数与豁免时间戳。关键方法：

| 方法 | 返回值 | 说明 |
|---|---|---|
| `Push(snapshot)` | `void` | 压入新快照并计算位移/时间差 |
| `IsInLegalTeleportWindow(now, window = 0.35f)` | `bool` | 是否处于合法传送豁免窗口内 |
| `ResetForNewRound(now)` | `void` | 清空回合级状态（保留累计统计） |

## 4. AntiCheatRuntime —— 运行时容器

| 成员 | 类型 | 说明 |
|---|---|---|
| `Config` / `Log` / `Tracker` / `Analyzer` / `Verdicts` / `Scanner` | 属性 | 注入的模块实例 |
| `Recorder` / `AiAnalyzer` / `HotReloader` / `RpcFlood` | 属性 | 网络与 AI 模块 |

| `GetOrCreateTrack(playerId, name)` | `PlayerTrack` | 取或建玩家轨迹 |

## 6. 其余模块接口

### 6.1 `ModScanner.Scan()`

返回 `ScanReport`，包含五个列表：

| 字段 | 内容 |
|---|---|
| `AllPlugins` | 全部已加载插件（`LoadedPluginInfo`） |
| `TrustedPlugins` | 白名单 / 内置信任命中的插件（字符串描述） |
| `GrayPlugins` | 灰名单或未收录插件（字符串描述） |
| `Violations` | 黑名单命中产生的证据（`PlayerId = -1`） |
| `Errors` | 扫描过程中的异常信息 |

### 6.2 `RpcFloodGuard.TryRecord(...)`

```csharp
bool TryRecord(int ownerId, string playerName, string rpcName, float now, bool loading)
```

| 返回 | 含义 |
|---|---|
| `true` | **应拦截**（已超阈值且处于熔断期，或本次触发熔断） |
| `false` | 放行 |

调用方（`RpcFloodPatches.Prefix`）只有在 `true` **且** 自己是房主时才 `return false` 丢弃。

### 6.3 `RpcAiAnalyzer`

| 方法 | 返回 | 说明 |
|---|---|---|
| `MaybeAnalyze(verdict)` | `void` | 自动触发；不满足门槛则静默返回 |
| `ManualAnalyze(playerId, verdict)` | `bool` | 手动触发（跳过门槛与冷却），是否成功发起 |
| `DrainPending(verdicts)` | `void` | **主线程**每帧调用，把 AI 产物提交给判定层 |
| `IsConfigured` | `bool` | 开关打开且密钥可用 |
| `ConfigProblem` | `string` | 配置缺失的人话原因；配置完整时为 `null` |
| `GetState(playerId)` | `AiAnalysisState` | 分析进度；从未分析过返回 `null` |

### 6.4 `ConfigHotReloader`

| 方法 | 说明 |
|---|---|
| `Prime()` | 建立初始快照，必须在首次 `Tick` 前调用 |
| `Tick(now)` | 每帧调用，内部按 0.5s 节流 |
| `MarkDirty()` | 主动标脏，强制下次检查 |

回调签名：`Action<IReadOnlyList<ConfigChange>>`，
`ConfigChange` 含 `Section / Key / OldValue / NewValue`。

## 7. 通用约定

1. **不抛异常**：所有面向游戏的接口都吞掉异常并返回保守值，调用方无需 try/catch。
   唯一例外是补丁内的检测逻辑，统一包在 `PatchHelper.Safe(action)` 中。
2. **不返回 null 集合**：`GetPlayers()` 等返回空集合而非 `null`。
3. **`-1` 表示无效**：PlayerId、ClientId 等失败时返回 `-1`，调用方必须先判 `>= 0`。
4. **全局证据用 `PlayerId = -1`**：静态扫描这类不归属具体玩家的证据走此约定。
