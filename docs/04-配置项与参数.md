# 04 · 配置项与参数

配置文件路径：

```
<游戏目录>/BepInEx/config/apex.cheat.ender.cfg
```

采用 BepInEx 原生 INI 风格，按分组组织。**任何一处改值都会立即落盘**，
且支持**热重载**——在游戏外用记事本改完保存，约 0.5 秒内自动生效，无需重启。

> ⚠️ 本文中「生效」一列是**核对代码后的事实**，不是设计意图。
> 标注为「空壳」的配置项**没有任何检测逻辑读取**，拨动开关不会产生任何效果。

---

## 1. 开哪些检测

| 配置项 | 类型 | 默认 | 说明 | 生效 |
|---|---|---|---|---|
| 扫描作弊插件 | bool | `true` | 扫描已加载插件并比对作弊特征库。误报极少，建议常开。 | ✅ |
| 检测瞬移和超速 | bool | `true` | 定时采样所有玩家位置，识别瞬移与超速。 | ✅ |
| 检查动作是否合法 | bool | `true` | 检查击杀、任务、通风管等动作的合法性。**关闭会跳过全部补丁挂载**。 | ✅ |
| 检测穿墙 | bool | `false` | 检测玩家坐标落入墙体碰撞体。开销较高且网络卡时易误判，默认关闭。 | ✅ |
| 输出详细日志 | bool | `false` | 打印每次采样的原始数据。仅排查误判时开启，日志增长很快。 | ✅ |

> 「检查动作是否合法」是**总开关**：为 `false` 时 `ApplyPatches()` 直接跳过，
> 连帧驱动都不会挂载，界面也不会出现。

## 2. 多久看一次位置

| 配置项 | 类型 | 默认 | 取值范围 | 说明 | 生效 |
|---|---|---|---|---|---|
| 看位置的间隔（秒） | float | `0.10` | 0.02 ~ 1.0 | 采样间隔。越小抓得越紧，越吃性能。 | ✅ |
| 开局后先不管几秒 | float | `4.0` | 0 ~ 30 | 开局宽限期，此期间不做运动学判定（出生传送会污染数据）。 | ✅ |
| 多小的位移算正常抖动 | float | `0.35` | — | 小于该距离的位移视为网络抖动，忽略。 | ✅ |

**调参建议**：觉得卡顿先把「看位置的间隔」调到 `0.2`；
若出现瞬移误报，先检查它是否被调得过大。

## 3. 怎么算跑太快

| 配置项 | 类型 | 默认 | 取值范围 | 说明 | 生效 |
|---|---|---|---|---|---|
| 允许比正常快几倍 | float | `1.6` | 1.0 ~ 5.0 | 速度上限倍率。`1.0` 表示不放水。 | ✅ |
| 一下挪多远算瞬移 | float | `4.5` | 0.5 ~ 20 | 单次采样位移阈值。 | ✅ |
| 超速几次才记下来 | int | `3` | 1 ~ 20 | 连续超速达到该次数才产生证据。 | ✅ |

### 瞬移判定的完整条件

瞬移需要**同时**满足两个条件才会被判罚：

```
① 位移 ≥ 「一下挪多远算瞬移」
② 隐含速度 = 位移 / 采样时间差  >  允许上限 × 3
```

条件 ② 是后加的降误报措施。早期版本只看距离，
导致**游戏卡顿或采样间隔被拉长时，正常玩家也会被误判为瞬移**。

## 4. 怎么算动作违规

| 配置项 | 类型 | 默认 | 取值范围 | 说明 | 生效 |
|---|---|---|---|---|---|
| 隔多远能砍人（额外放宽） | float | `0.75` | 0 ~ 5 | 在游戏设置距离之外额外放宽的容差。 | ✅ |
| 冷却能提前多久（秒） | float | `0.35` | 0 ~ 5 | 允许比角色冷却提前的秒数。 | ✅ |
| 做任务允许快几倍 | float | `1.5` | 1.0 ~ 5 | 任务点之间允许的最短耗时 = 直线距离/最大速度 ÷ 该倍数。 | ✅ |
| 隔多远能交任务（额外放宽） | float | `2.0` | 0 ~ 10 | 距任务点该距离内算「在任务点完成」。 | ✅ |
| 会议时允许走多远 | float | `0.75` | 0 ~ 5 | 会议期间允许的最大位移。 | ✅ |

**调参建议**：

- 出现「超距击杀」误报 → 适当调大 `隔多远能砍人`；
- 出现「远程任务」误报 → 调大 `隔多远能交任务`（多步任务、地图边缘常见）；
- 出现「任务速度异常」误报 → 调大 `做任务允许快几倍`。

## 5. 抓到之后怎么办

| 配置项 | 类型 | 默认 | 说明 | 生效 |
|---|---|---|---|---|
| 动手的方式 | 枚举 | `警告` | `忽略` / `警告` / `踢出` / `封禁` | ✅ |
| 自动踢人（不用手动点） | bool | `false` | 命中 `HighRisk` 及以上时自动处置。 | ✅ |

### 两者的关系

自动处置需要**同时**满足：命中 `HighRisk` 及以上 **且** `自动踢人 = true`
**且** `动手的方式` 属于「踢出 / 封禁」。

```
等级 ≥ HighRisk
  && 自动踢人 == true
  && 动手的方式 ∈ {踢出, 封禁}
        → 触发处置；其中「封禁」会额外带上封禁参数
```

也就是说：把 `动手的方式` 设成 `忽略` 或 `警告`，即使开了自动踢人也不会动手。
设置界面的手动处置按钮同样尊重这个档位。

## 7. 爬管道和滑索

| 配置项 | 类型 | 默认 | 说明 | 生效 |
|---|---|---|---|---|
| 抓普通人爬管道 | bool | `true` | 角色不具备通风能力（`Role.CanVent == false`）却使用通风管。 | ✅ |
| 抓隔着屏幕爬管道 | bool | `true` | 与通风管距离超过 `爬管道允许离多远`。 | ✅ |
| 抓伪造管道编号 | bool | `true` | 使用了不存在的管道编号（越界）。 | ✅ |
| 抓强迫别人爬管道 | bool | `true` | 非房主触发 `RpcBootFromVent`（权限提升类漏洞）。 | ✅ |
| 抓滑索滥用 | bool | `true` | 会议期间使用滑索。 | ✅ |
| 抓开会时爬管道 | bool | `true` | 会议期间使用通风管。 | ✅ |
| 爬管道允许离多远 | float | `2.0` | 距管道口该距离内算正常使用，范围 0.5 ~ 10。 | ✅ |

> 通风管相关判定对**角色能力**（`Role.CanVent`）而非阵营，
> 因此 Viper（船员阵营但能钻管道）不会被误判。角色信息不可用时一律放行。

## 8. 记录

| 配置项 | 类型 | 默认 | 说明 | 生效 |
|---|---|---|---|---|
| 记录谁进过房间 | bool | `true` | 每次进入对局写一行到 `PlayerHistory.txt`。 | ✅ |

## 9. 网络防护

| 配置项 | 类型 | 默认 | 取值范围 | 说明 | 生效 |
|---|---|---|---|---|---|
| 抓数据包刷屏 | bool | `true` | — | RPC 洪水检测总开关。 | ✅ |
| 10 秒内最多几次数据包 | int | `60` | 5 ~ 200 | 单个 OwnerId 在 10 秒窗口内的 RPC 上限。 | ✅ |
| 抓瞬移式位置同步 | bool | `true` | — | 关闭后阈值被设为 `int.MaxValue`，等效于停用。 | ✅ |
| 10 秒内最多几次强制同步 | int | `6` | 1 ~ 40 | 10 秒内 `RpcSnapTo` 次数达到该值即产生证据。 | ✅ |
| 抓开局乱开会 | bool | `true` | — | 开局保护期内报告尸体 / 开会即命中。 | ✅ |
| 开局后几秒内不许开会 | float | `15` | 0 ~ 60 | 开局保护期长度。 | ✅ |
| 抓超大数据包 | bool | `true` | — | 数据包超过 1400 字节即命中；房主直接丢弃。 | ✅ |

### RPC 洪水的行为细节

- 按 **OwnerId** 统计，滑动窗口 10 秒；
- 超过阈值 → 房主丢弃该 RPC，并进入熔断：加载/大厅阶段 `2.5s`，对局中 `1.0s`；
- 熔断期内直接返回「已拦截」，不再重复计数；
- 告警日志本身有 2 秒去重，避免刷屏。

## 11. 白名单

| 配置项 | 类型 | 默认 | 说明 | 生效 |
|---|---|---|---|---|
| 信任的插件 GUID | string | `""` | 英文逗号分隔。匹配插件的 BepInEx GUID。 | ✅ |
| 信任的插件名 | string | `""` | 英文逗号分隔。同时匹配插件名与程序集路径。 | ✅ |

匹配方式为**不区分大小写的子串匹配**。命中白名单的插件会被归入
`ScanReport.TrustedPlugins`，不产生任何证据。

> 除用户白名单外，`CheatSignatureDb.DefaultTrustedMarkers` 还内置了一份默认信任名单
> （TheOtherRoles / TownOfUs / Reactor / BetterAmongUs 等玩法与工具模组），
> 它们即使用户不配置也不会被判定。

## 12. AI 智能分析

| 配置项 | 类型 | 默认 | 取值范围 | 说明 | 生效 |
|---|---|---|---|---|---|
| 启用 AI 分析 | bool | `false` | — | 总开关。关闭时 `IsConfigured` 恒为 false。 | ✅ |
| 用哪家的模型 | string | `DeepSeek` | — | 显示名。当前目录中**只有 DeepSeek**。 | ✅ |
| 密钥 | string | `""` | — | `sk-` 开头的密钥。**明文存储**。 | ✅ |
| 命中几条规则才去问 AI | int | `1` | 1 ~ 20 | 低于该命中数不触发分析。 | ✅ |
| 同一个人隔多久再问一次 | int | `30` | 5 ~ 600 | 每玩家冷却，防止账单失控。 | ✅ |
| 等它多久算超时（秒） | int | `12` | 3 ~ 60 | 超时放弃本次分析。 | ✅ |
| 把玩家昵称一起发过去 | bool | `false` | — | 关闭时只发 `Player#<id>`。 | ✅ |

### 行为细节

- 触发条件：`命中数 ≥ 阈值` **且** 不在冷却内 **且** 未被 AI 确认过 **且** 配置完整；
- 密钥会被自动清洗（去首尾空白、去 `\r\n\t`）——HTTP 头带这些字符会导致 401；
- `用哪家的模型` 若填了目录中不存在的名字，会**静默回退到 DeepSeek**，不会报错；
- AI 失败（超时/网络/解析）**静默降级**，规则引擎继续工作，失败原因写入界面状态。

> ⚠️ **安全提示**：密钥以明文存放在配置文件中，不要把这个文件分享给他人。
